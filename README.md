# BOAT AI LAB

大村の出走表・展示情報と、端末内に保存するペーパーテストの記録アプリです。
出走表から着順確率を学習する初期モデル v1 を実装しています。収益性は未確認で、ペーパーテスト用です。

## 学習モデル v1

「自動予想」で6艇の出走表から、3連単・2連単・3連複の上位5候補と推定確率を表示します。
券種ごとに計算式を使い分けず、120通りの3連単分布から2連単・3連複を集約します。
候補を選ぶと買い目記録に券種・組み合わせ・推定確率を引き継ぎます。オッズは空欄に戻し、手動入力を必須にしています。

モデルはトップ3の着順尤度を使うPlackett–Luceモデルです。艇番6列と、全国勝率・全国2連率・当地勝率・モーター2連率・平均ST・F回数の計12特徴で学習します。数値は各レース内で中心化し、任意項目の欠損は同じレースの平均に補完します。全国勝率の欠損や範囲外の値は拒否します。展示、天候、結果、払戻、オッズ、選手ID、モーター番号は予想入力に使いません。モーター2連率は各レースの出走表に記載された値のみを使います。

開催日を古い順に60%・20%・20%へ分け、最初の60%だけで評価用モデルを学習します。確率の温度補正は中央20%の対数損失だけで選び、最後の20%で成績を測ります。同じ日を複数の区分に分けません。テスト後、配信専用モデルは利用可能な全レースで別に学習します。画面のテスト成績は全期間再学習前のモデルに対応します。配信用モデルの学習最終日以前のレースは、ブラウザで予想を拒否します。

初回のテストは791R中88的中（3連単最上位1点の的中率11.13%）、返還未反映の参考回収率84.55%でした。同じ期間の1-2-3固定は72的中・80.13%、全国勝率順は44的中・133.44%です。モデルが回収率で全基準を上回ったわけではありません。これらは後日取得した出走表を含む過去検証で、実運用の利益や確率の正しさを証明するものではありません。

予想は端末内で計算します。締切後・過去日・締切不明・出走表取得時刻不明・30分以上古い出走表は「参考記録」と表示します。締切前の区分もブラウザの時計に基づくもので、改ざんできない事前予想ログではありません。保存する際はモデル版、学習最終日、予想生成時刻、区分、出走表取得時刻を記録・CSV出力します。1R合計5,000円の既存上限を維持します。

Python 3.11以上と、`requirements.txt` に固定したNumPyが必要です。

```bash
python -m pip install -r requirements.txt
OPENBLAS_NUM_THREADS=1 python train_model.py
```

`data/prediction_model.json` に配信用係数、時系列評価、検証用の確率分布を保存します。3つの収集ワークフローで検証集計後に再学習します。同じ学習内容・集計ならモデル版と更新時刻を維持します。

## 今回追加した機能

- **過去検証**：出走表・結果がそろうレース数、締切前に6艇分の展示を保存できたレース数を表示。
- **固定ルールの比較**：3連単「1-2-3」と「全国勝率の高い順」を、同じ対象レースで1点100円として再集計。全期間と直近20%の開催日を切り替え可能。
- **公式結果との照合**：「結果入力」で、大村・3連単の的中一致をプレビューし、100円あたりの公式払戻を購入額に応じて保存。すでに確定した記録は上書きしません。
- 推定確率の初期値10%が入力ステップに合わず記録できなかった問題を修正。

### 検証の読み方

過去に取得した出走表による参考検証です。締切前に保存した予想の実運用成績ではありません。全国勝率が同じ場合は艇番順です。学習や結果を用いたルールの調整は行っていません。展示・気象・別途収集したモーター履歴は今回の比較に使いません。モーター番号だけで異なる使用期間の履歴を結合する処理もありません。

**結果CSVには返還情報がありません。** 固定ルールの回収率は返還未反映の参考値です。着順不一致の買い目は、返還対象でも支出100円・払戻0円として仮計算しています。正式な回収率ではありません。自動照合でも不一致を不的中に確定せず、返還の有無を公式で確認したうえで手動入力します。2連単・3連複の払戻も手動入力です。

6艇・6選手がそろわない出走表、結果の重複・不正、全国勝率の欠損は検証から除外します。締切前展示の件数は日別履歴も確認し、時刻が締切より前で、6艇分の公開済み展示と選手名が一致する場合だけ数えます。この件数だけで、全特徴量の締切前保存を証明するものではありません。

## 集計の再生成

追加のPythonライブラリは不要です（Python 3.11以上）。

```bash
python build_validation.py
```

- `data/validation_summary.json`：画面表示用の件数、期間、参考成績、入力CSVのSHA-256。
- `data/validation_races.csv`：各レースの正解、払戻、2ルールの買い目と取得時刻に関するフラグ。

入力・集計内容が同じ場合は集計時刻を維持します。3つの収集ワークフローがCSVを保存する前に再生成するため、収集の進行に応じて集計も更新されます。収集対象のない日や欠落した日は検証に含みません。日付範囲内の全レース収集完了を保証する表示ではありません。

## ローカル表示

リポジトリを静的HTTPサーバーで配信してください。GitHub Pagesでは更新の遅延を減らすため元リポジトリの `main/data/` を読み込み、それ以外では配信元の `./data/` を読み込みます。記録は配信元ごとに端末の `localStorage` に保存され、サーバーへ送信しません。
